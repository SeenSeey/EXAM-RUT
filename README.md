# Магистр — подготовка к вступительным экзаменам

Адаптивное PWA-приложение с тестовыми и открытыми заданиями. Работает полностью на клиенте, сохраняет сессии и статистику на устройстве и после первого открытия доступно без сети.

## Стек

React 18, TypeScript (strict), Vite, React Router, Zod, Vitest + Testing Library, vite-plugin-pwa/Workbox. Стили написаны на современном CSS без тяжёлой UI-библиотеки.

## Запуск

Требуется Node.js 18 или новее.

```bash
npm install
npm run dev
```

Другие команды:

```bash
npm run typecheck  # проверка TypeScript
npm run lint       # ESLint
npm test           # unit- и компонентные тесты
npm run build      # production-сборка в dist/
npm run preview    # локальный просмотр production-сборки
```

## Возможности

- шесть декларативно описанных треков: смешанные, тестовые и открытые, по всем или по выбранной дисциплине;
- выбор длины 10/20/50, весь пул и бесконечный режим;
- Fisher–Yates, отсутствие повторов в цикле, соотношение 70% тестовых и 30% открытых вопросов в смешанных сессиях;
- объяснения, пояснения к вариантам, цитаты источника;
- сравнение открытого ответа с эталоном и честная самооценка;
- восстановление незавершённой сессии и черновика после перезагрузки;
- итоги по темам и концепциям, повтор ошибочных вопросов;
- светлая/тёмная тема, клавиатурная навигация, aria-live и reduced motion;
- устанавливаемая PWA с кэшем оболочки и встроенного контента.

## Структура

```text
src/
  app/             провайдер состояния
  components/      общие UI-компоненты
  domain/          типы, треки, движок очереди и статистика (без React)
  features/        карточки MCQ и открытого вопроса
  pages/           страницы маршрутов
  repositories/    обнаружение и безопасная загрузка тем
  schemas/         runtime-валидация Zod
  storage/         версионированный localStorage
  test/            тестовые фикстуры и настройка
tasks/<subject>/   исходные JSON-файлы тем
```

UI не читает JSON и `localStorage` напрямую. `TopicRepository` обнаруживает данные через `import.meta.glob`, проверяет их и возвращает готовые доменные объекты. Движок сессий принимает `TrackDefinition`; случайность можно подменить seeded-генератором.

## Формат JSON

Файл темы имеет поля `topicId`, `topicTitle`, необязательные `promptVersion`, `conceptsIdentified` и массив `questions`.

Для `type: "mcq"` обязательны `id`, `concept`, `difficulty`, `question`, непустой `options`, корректный `correctIndex` и `explanation`. `rationales`, `questionType`, `sourceQuote` необязательны.

Для `type: "open"` обязательны `id`, `concept`, `difficulty`, `question`, `keyPoints`, непустой `modelAnswer`. `questionType` и `sourceQuote` необязательны.

Повреждённый файл не ломает приложение: он пропускается, а в development-консоли появляется понятная диагностика. Поскольку исходные числовые `topicId` повторяются в разных дисциплинах, уникальность проверяется внутри предметного каталога; внутренний ключ включает каталог.

## Как добавить тему

1. Создайте `tasks/<код-дисциплины>/topic-<номер>.json`.
2. Заполните его в описанном формате.
3. Запустите `npm run build` или dev-сервер.

Ручной импорт и изменения UI не нужны. Для красивого полного имени новой дисциплины добавьте соответствие её кода в `categoryNames` файла `src/repositories/topicRepository.ts`; без этого приложение покажет сам код.

## Как добавить трек

Добавьте объект `TrackDefinition` в реестр `src/domain/tracks.ts`: укажите допустимые типы вопросов и режим выбора дисциплины. Общие страницы настройки, сессии и итогов подхватят его автоматически. Для особого алгоритма можно добавить стратегию построения очереди в доменный слой, не копируя UI.

## Локальные данные

Ключ `exam-rut-state` в `localStorage` содержит версию схемы, настройки, агрегированную статистику и текущую сессию: очередь ключей, позицию, ответы и черновик. Несовместимые или повреждённые данные безопасно сбрасываются. В настройках доступно удаление всех данных с подтверждением.

Данные не отправляются на сервер и не синхронизируются между устройствами или браузерами.

## Статический деплой

`npm run build` создаёт каталог `dist/`. Его можно опубликовать на Netlify, Vercel или любом статическом хостинге. `base: './'` и hash-маршрутизация позволяют разместить сборку в подпапке GitHub Pages без серверных rewrite-правил. Service worker кэширует приложение и обновляет устаревший кэш автоматически.

Для GitHub Pages опубликуйте содержимое `dist/` через Actions или ветку `gh-pages`.

## Ограничения

- смысл открытого ответа автоматически не оценивается: пользователь сравнивает его с эталоном и выставляет самооценку;
- данные хранятся только локально и исчезнут при очистке данных браузера;
- SVG-иконка PWA универсальна, но некоторые старые платформы могут предпочитать отдельные PNG-иконки;
- новые JSON-файлы попадают в офлайн-сборку после следующего деплоя и обновления service worker.
