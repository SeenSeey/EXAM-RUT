1. Основы алгоритмов.
Алгоритм - это конечный набор четких инструкций или правил, описывающих порядок действий для решения определённой задачи
Ключевые свойства алгоритма
– Дискретность: Алгоритм разбит на отдельные, последовательно выполняемые шаги.
– Детерминированность (определенность): Каждый шаг определен однозначно. При одинаковых исходных данных алгоритм всегда выдает один и тот же результат и идет по одному пути.
– Конечность (результативность): Алгоритм должен завершать работу за конечное число шагов для любых допустимых входных данных.
– Массовость: Алгоритм применим к целому классу однотипных задач (меняются только входные данные).
– Понятность: команды должны быть сформулированы так, чтобы исполнитель (человек или компьютер) мог их выполнить.
Виды алгоритмов
– Последовательное выполнение
– Условное выполнение (ветвление)
– Циклы (повторение)
– Функции (подпрограммы)

2. Бинарный поиск.
Бинарный поиск - алгоритм поиска элемента в отсортированном массиве за O(log n). 
Идея: на каждом шаге сравниваем искомое значение с элементом посередине и отбрасываем ту половину, где элемента заведомо нет.

Требование. Данные должны быть отсортированы, а доступ по индексу - за O(1). Без сортировки алгоритм неприменим. 
Алгоритм. Границы lo, hi - где ещё может быть элемент. Пока lo <= hi: - a[mid] == x → нашли; - a[mid] < x → идём вправо: lo = mid + 1; - a[mid] > x → идём влево: hi = mid - 1. 
Реализация на Java
int binarySearch(int[] a, int x) {
   int lo = 0, hi = a.length - 1;
   while (lo <= hi) {
       int mid = lo + (hi - lo) / 2;   // без переполнения
       if (a[mid] == x) return mid;
       else if (a[mid] < x) lo = mid + 1;
       else hi = mid - 1;
   }
   return -1;                          // не найдено
}
Сложность. Время O(log n), память O(1).

3. «О-большое».
О-большое - это математический инструмент. Он показывает, как быстро растет время работы алгоритма (или объем требуемой памяти) при увеличении количества входных данных.
Примеры нотаций Big O
O(1): Константная сложность. Время выполнения алгоритма не зависит от размера входных данных. Например, доступ к элементу массива по индексу.
function getLastElement(arr) {
   return arr[arr.length - 1 ]
}
O(log n): Логарифмическая сложность. Время выполнения алгоритма растет медленно с увеличением размера входных данных. Например, бинарный поиск в отсортированном массиве.
// Бинарный поиск
function binarySearch(arr, target) {
   let left = 0;
   let right = arr.length - 1;
while (left &lt;= right) {
   let mid = Math.floor((left + right) / 2);


   if (arr[mid] === target) {
       return mid; // элемент найден
   } else if (arr[mid] &lt; target) {
       left = mid + 1; // искать в правой половине
   } else {
       right = mid - 1; // искать в левой половине
   }
}


return -1; // элемент не найден
}
O(n): Линейная сложность. Время выполнения алгоритма пропорционально размеру входных данных. Например, просмотр всех элементов в массиве.
function findMax(arr) {
   let max = arr[0];
   for (let i = 1; i < arr.length; i++) {
       if (arr[i] > max) {
           max = arr[i];
       }
   }
   return max;
}
O(n log n): Линейно-логарифмическая сложность. Время выполнения алгоритма растет быстрее, чем линейно, но медленнее, чем квадратично. Например, сортировка слиянием (merge sort).
O(n^2): Квадратичная сложность. Время выполнения алгоритма зависит от квадрата размера входных данных. Например, сортировка пузырьком (bubble sort).
function sumOfPairs(arr) {
   let sum = 0;
   for (let i = 0; i < arr.length; i++) {
       for (let j = 0; j < arr.length; j++) {
           sum += arr[i] + arr[j];
       }
   }
   return sum;
}
O(n^3): Кубическая сложность. Время выполнения алгоритма зависит от размера входных данных в кубе. Например, алгоритмы, которые имеют три вложенных цикла, такие как некоторые методы многомерной обработки данных.
function multiplyMatrices(matrix1, matrix2) {
   let result = [];
   const m = matrix1.length;
   const n = matrix2[0].length;
   const p = matrix2.length;


   for (let i = 0; i < m; i++) {
       result[i] = [];
       for (let j = 0; j < n; j++) {
           result[i][j] = 0;
           for (let k = 0; k < p; k++) {
               result[i][j] += matrix1[i][k] * matrix2[k][j];
           }
       }
   }
   return result;
}
O(n!): Факториальная сложность. Это самая высокая степень роста времени выполнения алгоритма. Время выполнения алгоритма растет факториально от размера входных данных. Этот тип сложности встречается, например, при переборе всех возможных комбинаций элементов, что делает его чрезвычайно неэффективным для больших значений n.
function permute(arr) {
   function swap(a, b) {
       const temp = arr[a];
       arr[a] = arr[b];
       arr[b] = temp;
   }


   function generate(n) {
       if (n === 1) {
           console.log(arr);
       } else {
           for (let i = 0; i < n - 1; i++) {
               generate(n - 1);
               if (n % 2 === 0) {
                   swap(i, n - 1);
               } else {
                   swap(0, n - 1);
               }
           }
           generate(n - 1);
       }
   }


   generate(arr.length);
}
Экспоненциальная сложность O(2^n). Сложность O(2^n) относится к экспоненциальной сложности, где время выполнения алгоритма увеличивается экспоненциально по мере увеличения размера входных данных. Это часто встречается в алгоритмах, которые решают проблемы методом "разделяй и властвуй" или используют рекурсию без оптимизации.
function fibonacci(n) {
   if (n <= 1) {
       return n;
   } else {
       return fibonacci(n - 1) + fibonacci(n - 2);
   }
}


4. Основные понятия сортировки.
Определение. Сортировка - перестановка элементов в порядок, заданный ключом и отношением сравнения (компаратором): по возрастанию или убыванию.
Свойства алгоритмов: - Устойчивость (stable) - сохраняет относительный порядок элементов с равными ключами (важно при сортировке по нескольким полям). Устойчивы: вставками, слиянием, подсчётом; неустойчивы: быстрая, пирамидальная, выбором. - На месте (in-place) - доп. память O(1). In-place: быстрая, пирамидальная; не in-place: слиянием (O(n)). - Адаптивность - быстрее на почти отсортированных данных (вставками → O(n) на уже отсортированном). - Сравнительная / несравнительная - сравнительная опирается только на сравнение пар (нижняя граница Ω(n log n)); несравнительная использует структуру ключа и может быть O(n). - Внутренняя / внешняя - данные помещаются в ОЗУ или нет (внешняя читает с диска блоками - external merge sort). Сложность. Нижняя граница для сравнительных сортировок - Ω(n log n) (n! перестановок, дерево решений даёт log(n!) ≈ n log n сравнений). Несравнительные обходят её ценой ограничений на ключи.

5. Алгоритмы устойчивой сортировки.
Суть: Сортировка называется устойчивой (stable), если она сохраняет исходный относительный порядок элементов с одинаковыми ключами (значениями, по которым происходит сортировка).Если на входе были два элемента A_1 и A_2 с одинаковыми ключами, и A_1 шел раньше A_2, то после устойчивой сортировки A_1 гарантированно останется перед A_2.Зачем это нужно на практике: При многоступенчатой сортировке объектов. Например, если сначала отсортировать список студентов по имени (устойчиво), а затем по номеру группы (устойчиво), то внутри каждой группы студенты останутся отсортированными по имени. Неустойчивая сортировка разрушит результаты предыдущего шага.
Устойчивые алгоритмы:
– Сортировка вставками (Insertion Sort): O(N^2) в худшем, O(N) в лучшем. Элемент перемещается назад, пока не встретит элемент, который строго меньше него, поэтому равные элементы не перепрыгивают друг друга.

– Сортировка слиянием (Merge Sort): O(N \log N) всегда. При слиянии подмассивов, если элементы равны, приоритет отдается элементу из левого (исходно более раннего) подмассива.

– Сортировка пузырьком (Bubble Sort): O(N^2). Равные элементы не меняются местами.

– Сортировка подсчетом (Counting Sort) / Поразрядная (Radix Sort): Не основаны на сравнениях, используют индексы для сохранения исходного порядка.

7. Непрактичные алгоритмы сортировки.
Непрактичными называют алгоритмы сортировки, которые имеют крайне высокую вычислительную сложность.
Основные примеры:
1. Bogosort (случайная сортировка)
Идея: Пока массив не отсортирован: случайным образом перемешивать элементы.
Пример: 3 1 2 -> 2 3 1 -> 1 3 2 -> 1 2 3
Сложность: средняя - O(n · n!), худшая - бесконечная (теоретически может никогда не закончиться)
2. Stooge Sort
Идея: Рекурсивно сортирует: первые 2/3 массива; последние 2/3; снова первые 2/3.
Сложность: Примерно O(n^2.709)
3. Slow Sort
Основан на принципе "умышленно делать всё максимально медленно".
Идея: рекурсивно сортировать левую половину; рекурсивно сортировать правую; сравнить максимумы; повторить.
Сложность: Экспоненциальная. Используется только для изучения рекурсии.
4. Bubble Sort (пузырьковая сортировка)
Хотя Bubble Sort применяется при обучении, для больших данных считается непрактичным.
Идея: Соседние элементы меняются местами, если стоят неправильно.
5 2 4 1 -> 2 5 4 1 -> 2 4 5 1 -> 2 4 1 5
После каждого прохода максимальный элемент "всплывает" в конец.
Сложность: лучшая - O(n), средняя - O(n²), худшая - O(n²),
5. Gnome Sort
Идея: Работает как человек, который переставляет книги на полке. Если элементы стоят правильно - идём вперёд. Если нет - меняем местами и возвращаемся назад.
Сложность: O(n²)

8. Рекурсия. Возможности применения. Стек вызовов.
Возможности применения. 
Стек вызовов Рекурсия - функция вызывает саму себя (прямо или косвенно), сводя задачу к подзадачам меньшего размера. 
Два обязательных компонента: 
базовый случай - условие остановки без рекурсивного вызова; 
рекурсивный случай - сведение к меньшей подзадаче, сходящейся к базовому. Без достижимого базового случая - бесконечная рекурсия и переполнение стека

int fact(int n) {
    if (n <= 1) return 1;      // базовый случай
    return n * fact(n - 1);    // рекурсивный случай
}

Стек вызовов. При каждом вызове в стек кладётся кадр (stack frame): параметры, локальные переменные, адрес возврата. Возврат снимает кадр. Например, fact(3) разворачивает цепочку кадров fact(3)→fact(2)→fact(1), затем сворачивает её обратно, перемножая. Глубина рекурсии = высота стека, а стек ограничен → слишком глубокая рекурсия даёт stack overflow. 

Применение: 
«разделяй и властвуй» - сортировки слиянием/быстрая, бинарный поиск;
обход деревьев и графов - DFS, обход каталогов файловой системы; 
перебор с возвратом (backtracking) - комбинации, N ферзей, лабиринты;
задачи с рекурсивной структурой - факториал, Фибоначчи, Ханойские башни; 
разбор выражений (рекурсивный спуск в парсерах).
	
Виды:
прямая / косвенная (A→A / A→B→A);
хвостовая (tail recursion) - рекурсивный вызов является последней операцией; тогда компилятор может переиспользовать текущий кадр (tail-call optimization), превращая рекурсию в цикл без роста стека. Оптимизируют Scheme, Scala; не оптимизируют JVM (Java) и Python. 

Проблемы и решения: 
переполнение стека при большой глубине → переписать в итерацию с явным стеком либо использовать хвостовую рекурсию + TCO; 
повторные вычисления (наивный Фибоначчи - экспоненциальное время) → мемоизация / динамическое программирование.

	Рекурсия vs итерация. Любую рекурсию можно выразить циклом (со своим стеком). Рекурсия короче и естественнее для рекурсивных структур, итерация экономит память и не рискует переполнением стека.

9. Стек. Очередь.
Стек - это коллекция, элементы которой получают по принципу «последний вошел, первый вышел» (LIFO). В отличие от списков, мы не можем получить доступ к произвольному элементу стека.
Операции
Стек предоставляет операции push (добавить на вершину), pop (снять с вершины), peek (вернуть верхний без удаления), count (кол-во элементов).
Применение стеков 
– Веб-браузеры. В них стеки применяются для управления историей навигации посещенных веб-страниц.
– Графическое программное обеспечение. В редакторах изображений или приложениях для рисования часто применяются функции отмены и повтора с использованием стеков.
– Вызовы функций и рекурсия.
Очередь - это коллекция, элементы которой получают по принципу «первый вошел, первый вышел» (FIFO).
Очереди часто используются в программах для реализации буфера, в который можно положить элемент для последующей обработки, сохраняя порядок поступления.
Очереди поддерживают эффективную вставку и удаление элементов. Но у них нет произвольного доступа к отдельным элементам.
Операции
Очередь предоставляет операции enqueue (добавляет в конец очереди), dequeue (удаляет значение в начале очереди),  peek (получить значение в начале), isEmpty (проверка на пустоту).

10. Хеш-таблицы. Коллизии. Быстродействие.
Хеш-таблица - структура для хранения пар «ключ–значение» с доступом в среднем за O(1). Ключ прогоняется через хеш-функцию, дающую индекс ячейки (бакета) в массиве, куда кладётся значение.
Хеш-функция отображает ключ в индекс [0, m). Требования: детерминированность, быстрое вычисление, равномерное распределение (чтобы ключи ложились по бакетам ровно). Обычно index = hash(key) mod m.
Коллизии - разные ключи дают один индекс. Неизбежны (ключей больше, чем бакетов - принцип Дирихле). 
Методы разрешения:
Цепочки (chaining) - каждый бакет хранит список (или дерево); при коллизии элемент добавляется в него. Просто, устойчиво к высокой загрузке.
Открытая адресация (open addressing) - при занятой ячейке ищем следующую свободную по правилу пробирования: линейное (i+1, i+2…), квадратичное (i+1², i+2²…), двойное хеширование. Экономит память (нет списков), но чувствительна к загрузке и кластеризации.
Коэффициент заполнения (load factor) α = n/m (элементов / бакетов). При превышении порога (в Java HashMap - 0.75) таблица расширяется (rehash): создаётся больший массив, элементы перераскладываются. Это держит цепочки короткими.

Что определяет скорость: качество хеш-функции (равномерность), контроль load factor (своевременный rehash), метод разрешения коллизий.

11. Список. Связный список.
Список (List) - это абстрактный тип данных, представляющий собой упорядоченную последовательность элементов. На уровне реализации он чаще всего бывает либо динамическим массивом, либо связным списком.
Связный список (Linked List) - это структура данных, состоящая из узлов (Nodes). Каждый узел содержит: Данные (payload) и Указатель (или ссылку) на следующий узел в последовательности.
Основные разновидности:
– Односвязный (Singly Linked): каждый узел ссылается только на следующий. Последний ссылается на null.
– Двусвязный (Doubly Linked): каждый узел имеет ссылки и на следующий, и на предыдущий элементы. Упрощает удаление и обход в обе стороны.
– Кольцевой (Circular): последний элемент ссылается на первый (бывает как одно-, так и двусвязным).
Оценка сложности операций:
– Поиск по индексу/значению: O(n) - приходится итерироваться с головы.
– Вставка/Удаление в начало: O(1)  просто меняем ссылки.
– Вставка/Удаление в конец: O(1) (если есть указатель на хвост).
– Вставка в середину (если узел уже найден): O(1).
Главное отличие от массива - элементы связного списка разбросаны по памяти хаотично. Из-за этого мы теряем кэш-локальность (СPU cache locality), что делает проход по списку медленнее, чем по массиву, несмотря на одинаковую теоретическую сложность O(n).

Set (множество) - коллекция уникальных элементов без дубликатов. Главная операция - проверка принадлежности (contains); порядок в общем случае не важен.
Операции: add, remove, contains, а также теоретико-множественные - объединение (union), пересечение (intersection), разность (difference).

13. Карты (Map). Реализации и особенности.
Map (Словарь, Ассоциативный массив) - структура данных, хранящая пары «ключ-значение», где каждый ключ уникален.
В стандартных библиотеках (например, в Java или C++) обычно есть две базовые реализации Map:
Хэш-таблица (HashMap / unordered_map)
В основе лежит массив и хэш-функция, которая преобразует ключ в индекс массива.
Сложность операций: В среднем O(1) для поиска, вставки и удаления. В худшем случае (когда все ключи дают один хэш) - O(n).
Разрешение коллизий: * Метод цепочек (Chaining): элементы с одинаковым хэшем выстраиваются в связный список (или дерево) внутри одной корзины.
Открытая адресация (Open Addressing): при коллизии ищется следующая свободная ячейка по определенному правилу (линейное пробирование и т.д.).
Особенность: Элементы не упорядочены. При росте количества элементов требуется дорогостоящая операция рехэширования (увеличение массива и перенос элементов).
Древовидная карта (TreeMap / map)
Обычно реализуется на базе Красно-черного дерева (сбалансированного двоичного дерева поиска).
Сложность операций: Поиск, вставка и удаление строго гарантируют O(log n).
Особенность: Ключи всегда отсортированы (требуется задать компаратор). Позволяет эффективно делать выборки поддиапазонов.

Основные операции:
put(key, value) - добавить или обновить пару;
get(key) - получить значение по ключу;
remove(key) - удалить пару;
containsKey(key) - проверить существование ключа
containsValue(value) - проверить наличие значения;
size() - количество элементов;
isEmpty() - проверка на пустоту;
clear() - удалить все элементы.

Выбор реализации зависит от задачи: HashMap - когда важна максимальная скорость доступа, TreeMap - когда необходимы упорядоченность и операции над диапазонами ключей.

14. Деревья. Особенности. Варианты.
Дерево - иерархическая структура из узлов: один корень, у каждого узла ≤1 родитель, циклов нет. Формально - связный ациклический граф; при N узлах ровно N-1 рёбер, между любыми двумя узлами единственный путь.
Терминология: корень, лист (без детей), родитель/потомок, поддерево, глубина узла (от корня), высота дерева (до самого дальнего листа), степень (число детей).
Обходы:
в глубину (DFS):
прямой (pre-order): корень → лево → право;
симметричный (in-order): лево → корень → право - у BST даёт отсортированный порядок;
обратный (post-order): лево → право → корень;
в ширину (BFS): по уровням (level-order).

15. Графы. Представление графов.
Граф (G) - это совокупность двух множеств: множества вершин (V, vertices) и множества ребер (E, edges), соединяющих эти вершины. G = (V, E).
Графы бывают ориентированными и неориентированными, взвешенными (когда у ребра есть «вес»/цена) и невзвешенными, связными (из любой вершины в любую вершину) и несвязными.
Основные способы представления графа в памяти:
– Матрица смежности - это квадратная матрица N × N, где N - число вершин.
Если вершины соединены: matrix[i][j] = 1
иначе: matrix[i][j] = 0

Преимущества:
~ очень быстро проверить наличие ребра;
~ простая реализация;
~ удобно для плотных графов.
Недостатки:
~ требует много памяти;
~ неэффективна для разреженных графов.
– Список смежности - для каждой вершины хранится список ее соседей.

Преимущества:
~ экономия памяти;
~ быстро обходить соседей;
~ лучший выбор для разреженных графов.
Недостатки:
~ проверить существование конкретного ребра медленнее, чем в матрице;
~ реализация немного сложнее.
– Список ребер - хранится просто список всех ребер.
[(u1, v1), (u2, v2), ...]
Часто применяется:
~ в алгоритме Краскала;
~ при чтении графов из файла;
~ в базах данных;
~ при хранении больших графов.

16. Алгоритмы обхода графов (DFS, BFS).
Граф - вершины (V) и рёбра (E). Представление: список смежности (у каждой вершины - её соседи; экономно для разреженных графов) или матрица смежности (V×V, быстрая проверка ребра, но O(V²) памяти). Обход = систематическое посещение всех достижимых вершин; в обоих алгоритмах нужен массив visited, чтобы не зациклиться.
DFS (обход в глубину). Идём вглубь по одному пути до упора, затем возвращаемся (backtrack) и пробуем другие. Реализация - рекурсия или явный стек.
void dfs(int v, List<List<Integer>> adj, boolean[] visited) {
    visited[v] = true;
    for (int u : adj.get(v))
        if (!visited[u]) dfs(u, adj, visited);
}

BFS (обход в ширину). Обходим по «уровням»: сначала все соседи источника, затем их соседи и т. д. Реализация - очередь.
	
void bfs(int s, List<List<Integer>> adj, boolean[] visited) {
    Queue<Integer> queue = new ArrayDeque<>();
    visited[s] = true; queue.add(s);
    while (!queue.isEmpty()) {
        int v = queue.poll();
        for (int u : adj.get(v))
            if (!visited[u]) { visited[u] = true; queue.add(u); }
    }
}


Сложность (оба): O(V + E) на списке смежности, O(V²) на матрице. Память - O(V) на visited плюс стек/очередь.
Применения:
DFS: компоненты связности, обнаружение циклов, топологическая сортировка, поиск мостов и точек сочленения, лабиринты, backtracking;
BFS: кратчайший путь в невзвешенном графе, обход по уровням, «степени разделения» в соцсетях.
Для кратчайшего пути во взвешенном графе ни DFS, ни BFS не годятся — нужен Дейкстра (или A*).

17. Алгоритмы поиска кратчайшего пути.
Кратчайший путь - это путь между двумя вершинами графа, имеющий минимальную стоимость. Стоимость пути может определяться: количеством ребер; суммой весов ребер.
Поиск кратчайшего пути используется в: GPS-навигации; компьютерных сетях; логистике; робототехнике; игровых картах; социальных сетях и т.д.
Основные алгоритмы
– Поиск в ширину (BFS) - используется только для невзвешенных графов, где все ребра имеют одинаковую стоимость. Для реализации обычно применяется очередь.
Преимущества: очень простой; самый быстрый для невзвешенных графов.
Недостаток: Не работает с различными весами ребер.
– Алгоритм Дейкстры - используется для графов с неотрицательными весами. Для каждой вершины хранится минимальное найденное расстояние, затем многократно: выбирается вершина с минимальным расстоянием; обновляются расстояния до ее соседей (релаксация). Обычно применяется очередь с приоритетом (Priority Queue), реализованная на основе кучи.
Преимущества: очень быстрый; широко используется; оптимален для большинства практических задач.
Недостаток: не работает при наличии отрицательных весов.
– Алгоритм Беллмана-Форда - используется тогда, когда возможны отрицательные веса. Каждое ребро многократно проверяется на возможность улучшить расстояние.
Преимущества: поддерживает отрицательные веса; обнаруживает отрицательные циклы.
Недостаток: работает значительно медленнее алгоритма Дейкстры.
– Алгоритм Флойда-Уоршелла - позволяет найти кратчайшие пути между всеми парами вершин. Используется матрица расстояний: последовательно рассматривается каждая вершина как промежуточная.
Если путь A → K → B короче существующего A → B то расстояние обновляется.
Преимущества: сразу получает расстояния между всеми вершинами; простая реализация.
Недостаток: очень медленный для больших графов.

18. Минимальное остовное дерево.
Остовное дерево (spanning tree) связного графа - подграф, соединяющий все вершины без циклов: ровно V вершин и V-1 рёбер. Минимальное остовное дерево (MST) - остовное дерево с наименьшей суммой весов рёбер.
Условия: граф неориентированный, связный, взвешенный. MST может быть не единственным (при равных весах рёбер).
Ключевая идея (почему работает жадность). Разрезающее свойство (cut property): для любого разбиения вершин на две части минимальное ребро между частями входит в некоторое MST. Поэтому оба классических алгоритма - жадные.
Алгоритм Краскала (Kruskal). Сортируем все рёбра по весу; идём по возрастанию и добавляем ребро, если оно не образует цикл (проверка через систему непересекающихся множеств - DSU/union-find). Останавливаемся на V-1 рёбрах. Время O(E log E).

int mst = 0, used = 0;
for (Edge e : edges) {
    if (dsu.find(e.u) != dsu.find(e.v)) {   // ребро не создаёт цикл
        dsu.union(e.u, e.v);
        mst += e.w; used++;
        if (used == V - 1) break;
    }
}

Алгоритм Прима (Prim). Растим дерево от произвольной вершины: на каждом шаге добавляем минимальное ребро, выходящее из уже построенного дерева наружу (кандидаты хранятся в приоритетной очереди/куче). Время O(E log V).

19. Динамическое программирование.
Динамическое программирование - это метод разработки алгоритмов, при котором сложная задача разбивается на более простые перекрывающиеся подзадачи, а результаты их решения сохраняются, чтобы не вычислять повторно.
Динамическое программирование используется, если задача обладает двумя свойствами:
1. Оптимальная подструктура
Оптимальное решение всей задачи строится из оптимальных решений ее подзадач.
Например: Чтобы найти кратчайший путь A → C через B, нужно знать кратчайшие пути: A → B; B → C.
2. Перекрывающиеся подзадачи
Одни и те же подзадачи возникают многократно. Например, при вычислении чисел Фибоначчи
Подходы к реализации
1. Сверху вниз (Top-Down)
Используется: рекурсия; запоминание результатов (мемоизация). При повторном вызове значение берется из памяти. 
Плюсы: проще написать; естественно выглядит.
Минусы: используется рекурсия; возможное переполнение стека.
2. Снизу вверх (Bottom-Up)
Используется цикл. Результаты вычисляются последовательно.Каждый следующий результат вычисляется по уже найденным.
Плюсы: быстрее; нет рекурсии; меньше расход памяти стека.
Алгоритм построения ДП-решения
Определить состояние - что означает dp[i][j]. Формулировка должна быть однозначной.
Записать рекуррентное соотношение - как состояние выражается через «меньшие».
Задать базу (начальные условия).
Определить порядок вычислений - так, чтобы к моменту расчёта состояния все нужные уже были посчитаны.
Указать ответ - в какой ячейке лежит результат.
Оценить сложность: время ≈ (число состояний) × (стоимость перехода); память ≈ число состояний (часто сокращается).
При необходимости - восстановление ответа (хранить предков или пересчитывать назад по таблице).


20. Жадные алгоритмы.
Жадный алгоритм (greedy) - на каждом шаге делает локально оптимальный выбор (лучший «прямо сейчас») и не пересматривает его, в надежде получить глобальный оптимум.



Когда даёт оптимум. Не всегда! Нужны два свойства:
свойство жадного выбора - локально оптимальный выбор входит в некоторое глобально оптимальное решение;
оптимальная подструктура - оптимум задачи складывается из оптимумов подзадач.
Если этих свойств нет - жадность даёт неоптимальный ответ.
Схема. Оценить/отсортировать варианты по критерию → на каждом шаге взять лучший допустимый → не откатывать назад.
Где работает (классика):
MST - Краскал, Прим;
кратчайшие пути - Дейкстра;
кодирование Хаффмана (сжатие);
выбор заявок (activity selection) - максимум непересекающихся интервалов;
дробный рюкзак (fractional knapsack) - берём по убыванию удельной ценности.
Где НЕ работает:
0/1 рюкзак — предмет нельзя делить; жадность по ценности/весу ошибается → нужно динамическое программирование;
размен монет в произвольной системе номиналов - «бери крупнейшую» не всегда оптимально: для номиналов 1, 3, 4 на сумму 6 жадный даёт 4+1+1 (3 монеты), а оптимум - 3+3 (2 монеты).
Плюсы/минусы. Просто и быстро (часто O(n log n) из-за сортировки), мало памяти; но не универсально и требует доказательства применимости для конкретной задачи.
Жадность vs динамика vs перебор. Перебор - всегда оптимум, но экспонента. Динамическое программирование - оптимум через подзадачи с запоминанием (когда жадность неверна). Жадность - быстрее всех, но только там, где доказано, что она применима.

21. Поиск подстроки.
Поиск подстроки - это задача нахождения вхождения одной строки в другую строку.
Где применяется
~ текстовых редакторах («Найти»); поисковых системах; анализе ДНК; компиляторах; и т.д.
Постановка задачи
Дано: текст длины n; подстрока длины m.
Необходимо: определить, входит ли подстрока в текст; найти первое или все вхождения.
– Наивный алгоритм - Подстрока последовательно сравнивается с каждой возможной позицией текста. Сравнение начинается с первой позиции. Если найдено несовпадение - образец сдвигается на один символ вправо.
Сложность: O(n⋅m)
Преимущества: очень простой; легко реализуется.
Недостатки: медленный на больших строках;
– Алгоритм Кнута–Морриса–Пратта (КМП) - При несовпадении не начинает поиск заново, а использует информацию о ранее совпавших символах. Для этого заранее вычисляется специальная таблица, которая называется префикс-функция.
Сложность: O(n+m)
Преимущества: линейная сложность; отсутствуют лишние сравнения; широко используется.
Недостаток: Более сложная реализация.
– Алгоритм Бойера–Мура - Сравнение начинается с конца образца, а не с начала. При несовпадении образец можно сразу сдвинуть на несколько символов. Если последний символ не совпадает, образец перескакивает сразу через несколько символов.
Сложность: O(n⋅m)
Преимущества: лучший алгоритм для длинных текстов; большие скачки при поиске.
Недостатки: Сложная реализация.
– Алгоритм Рабина–Карпа - Вычисляется хеш образца и каждого фрагмента текста такой же длины. Если хеши совпадают, выполняется обычное сравнение символов.
Сложность: O(n⋅m) (из-за возможных коллизий)
Преимущества: хорошо подходит для поиска множества образцов; эффективен при использовании хорошей хеш-функции.
Недостаток: Возможны ложные совпадения хешей
Как выбрать алгоритм
Наивный
маленькие строки; простые программы.
КМП
гарантированно линейное время; поиск одного образца.
Бойер–Мур
длинные тексты; поиск в редакторах; поиск в документах.
Рабин–Карп
поиск множества образцов; задачи с использованием хеширования.

22. Префиксные деревья.
Префиксное дерево (trie, бор) - дерево для хранения набора строк, где путь от корня до узла задаёт префикс. Каждое ребро помечено символом; строка - это путь от корня, а некоторые узлы отмечают концы слов.
Структура узла: ссылки на детей по символам (массив на алфавит или хеш-таблица) + флаг «здесь заканчивается слово».
class TrieNode {
    Map<Character, TrieNode> children = new HashMap<>();
    boolean isEnd;
}

Операции (L - длина ключа):
insert - идём по символам, создавая недостающие узлы, в конце ставим isEnd;
search - идём по символам; слово есть, если дошли до конца и isEnd == true;
startsWith (префикс) - то же, но без проверки isEnd.
Все три - O(L), независимо от числа хранимых слов.

void insert(TrieNode root, String w) {
    TrieNode cur = root;
    for (char c : w.toCharArray())
        cur = cur.children.computeIfAbsent(c, k -> new TrieNode());
    cur.isEnd = true;
}

Особенности:
общие префиксы хранятся один раз (экономия на словах с общим началом);
скорость зависит от длины ключа, а не от количества ключей (в отличие от хеш-таблицы и BST);
обход в глубину выдаёт слова в лексикографическом порядке;
минус - расход памяти: у каждого узла ссылки на детей (при массиве на весь алфавит много пустых).
Варианты:
сжатый бор (radix tree / Patricia) - цепочки из одного ребёнка схлопываются в одно ребро (экономит память);
троичный бор (ternary search tree) - компромисс между памятью и скоростью.
Быстродействие: insert/search/startsWith - O(L); память - до O(число_узлов × размер_алфавита).
Применения: автодополнение и поиск по префиксу, проверка орфографии и словари, T9, IP-маршрутизация (radix-деревья), автокомплит в поисковиках.

23. Бинарные деревья поиска.
Бинарное дерево - это древовидная структура данных, в которой каждый узел имеет не более двух потомков.

Бинарное дерево поиска - это бинарное дерево, обладающее дополнительными свойствами: значение левого потомка меньше значения родителя, а значение правого потомка больше значения родителя для каждого узла дерева.

Основные операции
– Поиск элемента - Сравниваем искомый ключ с текущим узлом.
– Вставка
– Удаление
если удаляем лист - просто удаляем;
если удаляем узел с одним потомком - потомок занимает его место;
если удаляем узел с двумя потомками - выбираем либо максимум левого поддерева, либо минимум правого.
– Минимум и максимум
Обход дерева
– Inorder (симметричный)
	Порядок: Лево → Корень → Право
Используется для получения отсортированных значений

– Preorder
Порядок: Корень → Лево → Право
Используется: копирование дерева; сериализация

– Postorder
Порядок: Лево → Право → Корень
Используется для удаления дерева


Высота дерева - длина самого длинного пути от корня до листа.
Деревья бывают сбалансированные и несбалансированные.

24. Сбалансированные деревья.
Сбалансированное дерево - двоичное дерево поиска (BST), которое автоматически поддерживает малую высоту при вставках и удалениях, гарантируя O(log n) на всех операциях. Проблема обычного BST: при вставке отсортированных данных оно вырождается в «цепочку» (список) высотой n, и поиск деградирует до O(n). Самобалансирующиеся деревья добавляют к правилам BST дополнительный инвариант и восстанавливают его поворотами (rotations).
Поворот (rotation) - локальная перестройка, меняющая связи «родитель–ребёнок» у 2–3 узлов, сохраняя порядок BST (лево < узел < право). Бывает левым и правым; из них собираются двойные (лево-право, право-лево).
AVL-дерево. Строгий баланс по высоте: для каждого узла высоты левого и правого поддеревьев различаются не более чем на 1. В узле хранится баланс-фактор (-1, 0 или 1); если он выходит за пределы этого диапазона, дерево перебалансируется поворотами. Высота ограничена ≈ 1.44·log₂n - дерево «плотнее», поэтому поиск чуть быстрее.

Красно-чёрное дерево (red-black). Ослабленный баланс через раскраску узлов. Пять свойств: каждый узел красный или чёрный; листья (NIL) чёрные; у красного узла оба ребёнка чёрные (нет двух красных подряд); все пути от узла до листьев содержат одинаковое число чёрных узлов (чёрная высота), а корень всегда чёрный. Следствие: самый длинный путь от корня к листу не более чем вдвое длиннее самого короткого, откуда высота ≤ 2·log₂(n+1) и O(log n).

Различие - в константах: у AVL меньше константа на поиске, у красно-чёрного - на изменениях. Практическое правило: AVL строго сбалансированы и дают более быстрый поиск ценой более частых поворотов; красно-чёрные балансируются мягче и требуют меньше поворотов при модификациях. Поэтому стандартные библиотеки почти повсеместно используют красно-чёрные деревья (std::map/std::set в C++, TreeMap/TreeSet в Java), а AVL берут для read-heavy сценариев.
Другие сбалансированные структуры: B-/B+-деревья (много детей, «широкие» - для дисков и БД), 2-3-деревья, splay-деревья (самоподстройка под частые запросы).
Применения: TreeMap/TreeSet и std::map (упорядоченные словари и множества), индексы БД и файловые системы (B+-деревья), планировщик процессов Linux CFS и отображение виртуальной памяти.

25. Куча (Heap). Приоритетная очередь.
Куча - это структура данных, представляющая собой почти полное бинарное дерево, для которого выполняется свойство кучи: если узел A - это родитель узла B, то ключ узла A больше (или меньше) ключа узла B (или равен ему).
Приоритетная очередь - это абстрактный тип данных, который поддерживает множество элементов, у каждого из которых есть некоторый приоритет. В отличие от обычной очереди (FIFO), извлечение элемента происходит на основании его приоритета.
Куча является наиболее эффективной стандартной реализацией приоритетной очереди.
Виды куч по свойству порядка:
– Min-Heap: Приоритет любого узла меньше или равен приоритету его потомков. Корень содержит минимальный элемент.
– Max-Heap: Приоритет любого узла больше или равен приоритету его потомков. Корень содержит максимальный элемент.
Представление в памяти
Кучу обычно хранят в массиве, без явных указателей. Для элемента с индексом i: левый сын: 2i + 1, правый сын: 2i + 2, родитель: (i - 1) / 2.
Основные операции
– Вставка (Insert) - Новый элемент помещается в конец массива. Выполняется просеивание вверх (Sift Up): пока элемент больше (или меньше для Min Heap) родителя, они меняются местами.
Сложность: O(log n)
	– Удаление максимума/минимума - Удаляется корень. Алгоритм: Корень заменяется последним элементом массива. Последний элемент удаляется. Выполняется просеивание вниз.
Сложность: O(log n)
– Получение максимума/минимума -  Корень дерева.
Сложность: O(1)
– Построение кучи - Из произвольного массива. Алгоритм: начиная с последнего внутреннего узла, выполняется Heapify вниз.
Сложность: O(n)
– Heapify (Просеивание) - Используется после удаления элемента или построения кучи. Алгоритм: сравнить вершину с детьми; выбрать большего (или меньшего); поменять местами; повторять, пока свойство кучи не восстановится.
Сложность: O(log n)

Кучи используются для: реализации очередей с приоритетом, сортировок и поиска кротчайших путей.

26. Алгоритмы сжатия данных.
Сжатие данных - уменьшение объёма данных за счёт устранения избыточности. Две большие категории: без потерь (lossless) - исходные данные восстанавливаются точно, и с потерями (lossy) - часть несущественной информации отбрасывается ради большего сжатия.
Сжатие без потерь. Делится на два класса.
Энтропийное кодирование - присваивает частым символам короткие коды, редким - длинные.
RLE (Run-Length Encoding) - заменяет последовательности одинаковых значений парой «значение + счётчик»; хорошо сжимает данные с длинными сериями (простая графика, иконки). Очень прост, но бесполезен на «пёстрых» данных.
Код Хаффмана - жадный алгоритм: строит по частотам символов двоичное дерево, давая префиксный код (ни один код не является префиксом другого). Символ с высокой вероятностью кодируется коротким кодом, с низкой - длинным, что уменьшает среднюю длину сообщения.
Арифметическое кодирование - в отличие от Хаффмана, кодирует всё сообщение в одно число; достигает более высоких коэффициентов сжатия и допускает дробное число бит на символ.
Словарные методы (семейство Лемпеля-Зива) - заменяют повторяющиеся фрагменты ссылками на предыдущее вхождение.
LZ77 - заменяет повторно встречающиеся данные парами (длина, смещение), указывающими в скользящее окно (sliding window) прошлого вывода
LZ78 / LZW - строят явный словарь встреченных строк; LZW строит словарь входных последовательностей в процессе кодирования (используется в GIF, TIFF).
DEFLATE - комбинация: сначала LZ77-кодирование, затем кодирование Хаффмана; основа gzip, ZIP и PNG

Сжатие с потерями. Отбрасывает несущественные детали, опираясь на особенности человеческого восприятия; большинство таких алгоритмов основаны на трансформирующем кодировании (transform coding). Применяется к медиа: JPEG (изображения), MP3/AAC (звук), H.264/H.265 (видео).

27. Поиск циклов в графах.
Цикл в графе - это путь в графе, который начинается и заканчивается в одной и той же вершине, при этом остальные вершины пути (кроме первой и последней) не повторяются.
Зачем искать циклы?
при топологической сортировке;
в компиляторах (поиск циклических зависимостей);
в графах зависимостей проектов;
при анализе сетей;
в базах данных;
при обнаружении дедлоков.
Поиск цикла в неориентированном графе
Используется DFS (поиск в глубину).
Во время обхода вершина помечается как посещенная.
Если из текущей вершины можно перейти в уже посещенную вершину, которая не является родителем, значит найден цикл.
Сложность: O(V + E), где V - кол-во вершин, а E - рёбер.
Поиск цикла в ориентированном графе
Используется DFS с тремя состояниями вершин. Каждая вершина может быть: White (не посещена), Gray (находится в текущем пути DFS), Black (полностью обработана).
Если во время DFS найдено ребро в серую вершину, значит мы вернулись в текущий путь. Следовательно, существует цикл.
Сложность: O(V + E)
Поиск цикла через топологическую сортировку
Работает только для ориентированных графов.
Идея: Если удалось выполнить топологическую сортировку, то граф ацикличен (DAG). Если после алгоритма Кана остались необработанные вершины - существует цикл.
Поиск циклов с помощью системы непересекающихся множеств (DSU)
Используется для неориентированных графов.
Идея: Если очередное ребро соединяет вершины, которые уже находятся в одном множестве, значит найден цикл.
Когда какой метод использовать?
Неориентированный граф:
DFS с проверкой родителя - самый распространённый способ.
DSU - если граф строится постепенно (например, рёбра добавляются по одному).
Ориентированный граф:
DFS с тремя цветами - классический метод.
Топологическая сортировка - если одновременно нужно проверить, является ли граф DAG.

28. Топологическая сортировка.
Топологическая сортировка - линейное упорядочение вершин ориентированного графа такое, что для каждого направленного ребра u→v вершина u стоит в порядке раньше v. Иначе говоря, все рёбра «смотрят вперёд».
Условие существования. Топологический порядок возможен тогда и только тогда, когда в графе нет ориентированных циклов, то есть граф является DAG (ориентированным ациклическим графом). Для одного DAG может существовать несколько валидных топологических порядков (когда несколько вершин независимы).
Алгоритм Кана (Kahn, через BFS и полустепени захода). Опирается на in-degree - число входящих рёбер. Идея: DAG всегда имеет хотя бы одну вершину с in-degree = 0; выводим такие вершины, удаляем их вместе с исходящими рёбрами, появляются новые вершины с нулевой полустепенью.

List<Integer> topoSort(int V, List<List<Integer>> adj) {
    int[] indegree = new int[V];
    for (int v = 0; v < V; v++)
        for (int u : adj.get(v)) indegree[u]++;

    Queue<Integer> queue = new ArrayDeque<>();
    for (int v = 0; v < V; v++)
        if (indegree[v] == 0) queue.add(v);

    List<Integer> result = new ArrayList<>();
    while (!queue.isEmpty()) {
        int v = queue.poll();
        result.add(v);
        for (int u : adj.get(v))
            if (--indegree[u] == 0) queue.add(u);
    }
    // обработаны не все вершины → в графе есть цикл (не DAG)
    return result.size() == V ? result : null;
}	

Бонус: обнаружение цикла - естественный побочный эффект алгоритма (если обработаны не все вершины, значит есть цикл). Interview Kickstart
Алгоритм на DFS. Запускаем обход в глубину; вершину добавляем в стек после обработки всех её потомков (post-order), в конце разворачиваем стек. Циклы ловятся раскраской «белый-серый-чёрный»: встреча серой вершины = обратное ребро = цикл.
Сложность (оба метода): O(V + E) по времени - каждая вершина и каждое ребро обрабатываются константное число раз; O(V) дополнительной памяти (стек рекурсии / очередь + массив in-degree).

29. Параллельные и распределенные алгоритмы.
Параллельный алгоритм - алгоритм, части которого одновременно выполняются на нескольких процессорах или ядрах одного вычислительного устройства с общей памятью.
Не любую задачу можно эффективно распараллелить. Если между её частями существует сильная зависимость, потоки будут постоянно ждать друг друга, и выигрыш в производительности окажется небольшим.
Основные проблемы параллельных алгоритмов:
– синхронизация потоков при работе с общими данными;
– гонки данных (Race Condition), возникающие при одновременном изменении одной переменной;
– балансировка нагрузки, когда работа должна быть распределена между потоками примерно одинаково;
– накладные расходы на создание потоков и синхронизацию, которые могут свести на нет выигрыш от параллельности.
Примерами задач, хорошо подходящих для параллельной обработки, являются обработка больших массивов, поиск максимума или минимума, сортировка методом «разделяй и властвуй» (например, Merge Sort), обработка изображений и научные вычисления.

Представим, что данных уже настолько много, что они не помещаются на один компьютер. Например: 500 ТБ логов. Даже если процессор очень быстрый, памяти не хватит. Поэтому появляются десятки или тысячи серверов.
Распределённый алгоритм - алгоритм, выполняющийся на нескольких независимых компьютерах (узлах), которые взаимодействуют между собой по сети.
Главное отличие распределённых алгоритмов от параллельных состоит в том, что при параллельных вычислениях используется общая память одного компьютера, а при распределённых взаимодействие происходит по сети, что значительно медленнее обращения к памяти.
Основные проблемы распределенных алгоритмов:
– задержки передачи данных по сети;
– возможность отказа отдельных узлов;
– обеспечение согласованности данных между разными компьютерами;
– минимизация количества сетевых сообщений, поскольку обмен данными часто дороже самих вычислений.
Распределенные алгоритмы применяются в облачных сервисах, поисковых системах, банковских системах, системах хранения данных и при обработке больших данных.

30. Алгоритмы для работы с большими данными.
Большие данные (Big Data) - данные такого объёма, разнообразия и скорости поступления, что классические алгоритмы, рассчитанные на загрузку всего набора в оперативную память одной машины, неприменимы. Резкий рост объёмов привёл к появлению отдельной категории алгоритмов и к полному переосмыслению алгоритмических парадигм. Базовые ограничения, вокруг которых всё строится: данные не помещаются в RAM (только на диск или на кластер), проход по данным дорог (в идеале - один проход), точный ответ часто не нужен - достаточно приближённого с гарантией погрешности.
Ключевые подходы:
Внешняя сортировка (external merge sort). Когда массив не влезает в память, его сортируют по частям: читают порции, помещающиеся в RAM, сортируют их в памяти, сбрасывают на диск отсортированными «серия­ми» (runs), затем сливают серии слиянием (merge). Это класс внешних алгоритмов, которые легко обрабатывают огромные объёмы; именно merge sort лежит в основе сортировки в распределённых системах.
Потоковые алгоритмы (streaming). Обрабатывают данные «на лету», за один проход и с сублинейной (обычно O(log n) или O(1)) памятью, не храня весь поток. Применяются, когда данные приходят непрерывно (логи, клики, сенсоры) и хранить их целиком нельзя.
Вероятностные структуры (sketches). Компактные приближённые «сводки» потока с доказуемыми границами ошибки. Незаменимый инструмент современных архитектур для обработки потоков и очень больших наборов.

Ключевое свойство Bloom filter: он «не лжёт в отрицательную сторону» - если фильтр говорит «нет», этому можно доверять абсолютно; ложные срабатывания возможны только в положительную сторону. Используется, чтобы избежать лишних обращений к диску. HyperLogLog (Flajolet и др., 2007) оценивает число уникальных элементов, тогда как точное решение через hash-set потребовало бы гигабайты. Все три структуры реально работают в продакшене через Redis, Cassandra, Spark, BigQuery, Flink.
Резервуарная выборка (reservoir sampling) - компактный пример потокового алгоритма (k=1 для простоты обобщается на k):

int reservoirSample(Iterator<Integer> stream) {
    int result = 0, count = 0;
    Random rnd = new Random();
    while (stream.hasNext()) {
        int x = stream.next();
        count++;
        // i-й элемент занимает место с вероятностью 1/i
        if (rnd.nextInt(count) == 0) result = x;
    }
    return result;
}

MapReduce. Модель распределённой обработки: задача дробится и выполняется параллельно на кластере из тысяч обычных машин по принципу shared-nothing (мапперы работают над своими данными независимо). Поток данных: Map → Shuffle/Sort → Reduce.
map(k1, v1) → [(k2, v2)] — читает свою порцию входа, применяет функцию, выдаёт промежуточные пары.
shuffle & sort - промежуточные пары группируются и сортируются по ключу и передаются нужным редьюсерам; фреймворк гарантирует, что вход каждого редьюсера отсортирован по ключу (сортировка выполняется слиянием - тем самым внешним merge sort).
reduce(k2, [v2]) → [(k3, v3)] - агрегирует все значения с одним ключом.
Классический пример - подсчёт слов (word count): map выдаёт (слово, 1), reduce суммирует единицы по каждому слову.

Распределённые фреймворки. Hadoop/HDFS (дисковый MapReduce), Apache Spark (обработка в памяти, на порядок быстрее для итеративных задач), потоковые системы Flink и Kafka Streams. Поверх них - распределённое машинное обучение и обработка больших графов.

31. Алгоритмы для работы с потоками данных.
Представьте, что вам нужно обработать:
._. все запросы к Google за сутки;
._. все транзакции банка;
._. данные с миллиона IoT-датчиков;
._. ленту Twitter.
Объем данных может быть настолько большим, что его невозможно полностью загрузить в память, поэтому возникает задача:
Как получить нужный результат, если данные приходят непрерывно и хранить их целиком нельзя?
Поток данных - это последовательность элементов, поступающих один за другим в режиме реального времени.
Основная идея в потоковых алгоритмах: Получили элемент -> обновили состояние -> забыли элемент
Главная цель - использовать один проход по данным и минимальный объём памяти.
Для сложных задач применяются специальные структуры данных и вероятностные алгоритмы, такие как Bloom Filter (видел ли я?) и HyperLogLog (сколько разных?), которые экономят память ценой небольшой вероятности ошибки.
