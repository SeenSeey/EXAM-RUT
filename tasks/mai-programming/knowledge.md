# Технологии программирования

> Материал для трека «МАИ», подготовленный по программе вступительного экзамена и конспекту mai.md.

### 1. Основы языков программирования

* **Типы данных:**
* *Примитивные:* `int`, `float`, `char`, `bool`.
* *Составные:* Массивы, структуры (`struct`), объединения (`union`).
* *Типизация:* Статическая / Динамическая, Строгая (Сильная) / Слабая.


* **Рекурсия:** Вызов функции из самой себя.
* *База рекурсии:* Условие выхода, предотвращающее бесконечные вызовы.
* *Рекурсивный шаг:* Уменьшение задачи до подзадачи.
* *Хвостовая рекурсия (Tail Recursion):* Рекурсивный вызов является последней операцией функции (оптимизируется компилятором без переполнения стека).

### 2. Объектно-ориентированное программирование (ООП)

* **Класс и Объект:** Класс — шаблон/чертеж, описывающий состояние (поля) и поведение (методы). Объект — конкретный экземпляр класса в памяти.
* **Три (четыре) столпа ООП:**
* **Инкапсуляция:** Объединение данных и методов их обработки внутри класса и ограничение прямого доступа к ним (`private`, `protected`, `public`).
* **Наследование:** Создание нового класса (потомка) на основе существующего (предка) с унаследованием его свойств и методов.
* **Полиморфизм:** Способность объектов с одинаковым интерфейсом иметь разную реализацию (например, переопределение методов).
* *Абстракция:* Выделение только существенных характеристик объекта с игнорированием неважных деталей.


* **Виртуальные функции и VTABLE:**
* *Виртуальная функция:* Метод, который может быть переопределен в классах-потомках.
* *Таблица виртуальных функций (VTABLE):* Механизм **позднего (динамического) связывания**. Для класса с виртуальными методами компилятор создает массив указателей на их актуальные реализации. Каждый объект содержит скрытый указатель `vptr` на VTABLE своего класса.


* **Абстрактный класс:** Класс, содержащий хотя бы одну **чисто виртуальную функцию** (`virtual void draw() = 0;`). Нельзя создать экземпляр абстрактного класса; он служит базовым интерфейсом.

### 3. Динамические структуры данных

```
               [ Структуры данных ]
                      /    \
        Последовательные    Связанные
          (Массивы)      (Списки, Деревья)

```

| Структура | Реализация | Доступ по индексу | Вставка / Удаление |
| --- | --- | --- | --- |
| **Вектор / Динамический массив** | Последовательные ячейки памяти | $O(1)$ | $O(n)$ в середину/начало, $O(1)$ amortized в конец |
| **Связный список (Singly / Doubly Linked)** | Узлы с указателями `next` / `prev` | $O(n)$ | $O(1)$ при известном указателе на узел |
| **Двоичное дерево поиска (BST)** | Иерархические узлы (`left`, `right`) | Поиск: $O(\log n)$ средн., $O(n)$ худш. | $O(\log n)$ средн., $O(n)$ худш. |

* **Балансировка деревьев:** Сбалансированные деревья (AVL-деревья, Красно-черные деревья) гарантируют высоту $O(\log n)$ за счет поворотов узлов, предотвращая вырождение дерева в список.

### 4. Инженерия программного обеспечения (ПО)

* **Жизненный цикл ПО (SDLC):** Совокупность стадий от идеи до снятия системы с эксплуатации: *Анализ требований $\rightarrow$ Проектирование $\rightarrow$ Реализация (Кодинг) $\rightarrow$ Тестирование $\rightarrow$ Развертывание $\rightarrow$ Поддержка*.
* **Методологии разработки:**
* **Каскадная модель (Waterfall):** Строго последовательное прохождение этапов. Высокие риски при изменении требований.
* **Итеративные / Агильные модели (Agile, Scrum, Kanban):** Разработка короткими циклами (спринтами) с частым получением работающего продукта и адаптацией под меняющиеся требования.


* **Критерии качества ПО (ISO/IEC 25010):**
1. *Функциональная пригодность (Functional Suitability).*
2. *Надежность (Reliability):* Отказоустойчивость, восстанавливаемость.
3. *Производительность / Эффективность (Performance Efficiency).*
4. *Удобство использования (Usability).*
5. *Сопровождаемость (Maintainability):* Модульность, читаемость кода, тестируемость.
6. *Переносимость (Portability).*


* **Спецификация ПО (SRS — Software Requirements Specification):** Формальный документ, четко описывающий все функциональные и нефункциональные требования к создаваемой программной системе.
