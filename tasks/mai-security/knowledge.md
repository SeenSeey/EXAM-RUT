# Информационная безопасность

> Материал для трека «МАИ», подготовленный по программе вступительного экзамена и конспекту mai.md.

### 1. Криптография

* **Симметричное шифрование:**
* *Принцип:* Для зашифрования и расшифрования используется **один и тот же секретный ключ**.
* *Алгоритмы:* AES (Advanced Encryption Standard), DES/3DES, GOST R 34.12-2015 («Кузнечик», «Магма»).
* *Плюсы:* Высокая скорость работы, малая вычислительная сложность.
* *Минусы:* Проблема безопасной передачи ключа между участниками exchange, сложность масштабирования ($N(N-1)/2$ ключей для $N$ пользователей).


* **Асимметричное шифрование (с открытым ключом):**
* *Принцип:* Используется пара ключей — **открытый (Public Key)** для зашифрования и **закрытый (Private Key)** для расшифрования.
* *Математическая основа:* Односторонние функции с потайным входом (факторизация больших чисел, дискретное логарифмирование).
* *Алгоритмы:* RSA, ECC (эллиптические кривые), ElGamal, ГОСТ Р 34.10-2012.
* *Плюсы:* Простая дистрибуция открытых ключей, поддержка ЭП.
* *Минусы:* Низкая скорость (в 1000+ раз медленнее симметричных). На практике применяют *гибридные схемы* (асимметрия передает симметричный сессионный ключ).


* **Хэш-функции:** Односторонние отображения данных произвольной длины в строку фиксированной длины (дайджест). Свойства: стойкость к поискам прообраза и коллизий. Примеры: SHA-256, SHA-3, Стрибог (ГОСТ Р 34.11-2012).
* **Электронная цифровая подпись (ЭП / ЭЦП):**
* Обеспечивает **целостность**, **аутентификацию авторства** и **неотрекаемость**.
* *Алгоритм формирования:* Хэш от сообщения зашифровывается *закрытым ключом* отправителя: $Sign = E_{PrivKey}(Hash(M))$.
* *Алгоритм проверки:* Получатель расшифровывает подпись *открытым ключом* отправителя и сравнивает с вычисленным хэшем полученного сообщения: $D_{PubKey}(Sign) \stackrel{?}{=} Hash(M)$.


* **Сертификаты и Инфраструктура открытых ключей (PKI):**
* *Цифровой сертификат (X.509):* Документ, связывающий открытый ключ с личностью владельца.
* *Удостоверяющий центр (CA / Certificate Authority):* Доверенная треть сторона, которая подписывает сертификаты своим закрытым ключом.

### 2. Сетевая безопасность

* **Классификация атак:**
* *Пассивные (без изменения данных):* Прослушивание трафика (Sniffing), анализ потоков.
* *Активные (с изменением данных):*
* **Man-in-the-Middle (MitM):** Перехват и подмена трафика между узлами.
* **Spoofing:** Подмена IP или MAC-адреса.
* **DoS / DDoS:** Атака типа «отказ в обслуживании» (SYN-flood, UDP-flood, HTTP-flood) для исчерпания ресурсов сервера.
* **Инъекции (SQLi, XSS):** Внедрение вредоносного кода через входные параметры.




* **Межсетевые экраны (Firewalls / Брандмауэры):**
* *Пакетный фильтр (L3/L4):* Фильтрация по IP-адресам, портам и флагам (Stateless).
* *Фильтр с учетом состояния соединений (Stateful Inspection / L4):* Отслеживает сессии (TCP handshake) и пропускает только ответный трафик.
* *Шлюз прикладного уровня (WAF / L7):* Анализирует содержимое протоколов прикладного уровня (HTTP, FTP, DNS).


* **Системы обнаружения/предотвращения атак (IDS / IPS):**
* *IDS (Detection):* Пассивно анализирует копию трафика и сигнализирует об угрозах.
* *IPS (Prevention):* Устанавливается «в разрыв» (In-line) и способна блокировать вредоносный трафик.
* *Методы детектирования:* На основе сигнатур (Signature-based) и на основе аномалий (Anomaly-based / ML).
