### 1. Проектирование БД и ER-модель

* **Этапы проектирования:**
1. *Концептуальное:* Сбор требований, создание ER-диаграммы (не зависит от конкретной СУБД).
2. *Логическое:* Преобразование ER-модели в реляционную схему (таблицы, связи, нормализация).
3. *Физическое:* Выбор типов данных, создание индексов, настройка хранения на диске под конкретную СУБД (PostgreSQL, Oracle, MySQL).


* **ER-модель (Entity-Relationship / Сущность-Связь):**
* *Сущность (Entity):* Объект предметной области (например, "Студент").
* *Атрибут (Attribute):* Свойство сущности (например, "Имя", "Дата рождения").
* *Связь (Relationship):* Логическая связь между сущностями.


* **Типы связей (Кардинальность):**
* `1:1` (Один-к-одному) — например, Гражданин $\leftrightarrow$ Паспорт.
* `1:M` (Один-ко-многим) — например, Группа $\leftrightarrow$ Студенты.
* `M:M` (Многие-ко-многим) — например, Студенты $\leftrightarrow$ Курсы (в реляционных БД реализуется через промежуточную связующую таблицу).

### 2. Реляционная модель и Нормализация

* **Терминология:**
* *Отношение (Relation)* = Таблица.
* *Кортеж (Tuple)* = Строка/Запись.
* *Атрибут (Attribute)* = Столбец/Поле.
* *Домен:* Допустимое множество значений для атрибута.


* **Ограничения целостности:**
* *Целостность сущностей:* Первичный ключ должен быть уникальным и не может содержать `NULL`.
* *Ссылочная целостность:* Внешний ключ должен либо ссылаться на существующее значение первичного ключа в связанной таблице, либо быть `NULL`.


* **Нормализация и Нормальные формы (НФ):**
* *1НФ (Первая нормальная форма):* Все атрибуты атомарны (неделимы), нет повторяющихся групп/массивов в одном поле.
* *2НФ:* Находится в 1НФ + каждый ненужный ключевой атрибут **функционально полно зависит от всего Первичного Ключа** (актуально для составных ключей).
* *3НФ:* Находится во 2НФ + **нет транзитивных зависимостей** (ненуклевой атрибут не должен зависеть от другого неключевого атрибута).
* *НФБК (Boyce-Codd / BCNF):* Строгая версия 3НФ. Каждая детерминанта (то, от чего зависит атрибут) является потенциальным ключом.

### 3. Язык SQL (DDL и DML)

* **DDL (Data Definition Language) — Работа со структурой:**

```sql
-- Создание таблицы
CREATE TABLE Students (
    student_id INT PRIMARY KEY AUTO_INCREMENT,
    first_name VARCHAR(50) NOT NULL,
    last_name VARCHAR(50) NOT NULL,
    group_id INT,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    FOREIGN KEY (group_id) REFERENCES Groups(group_id) ON DELETE SET NULL
);

-- Изменение структуры
ALTER TABLE Students ADD COLUMN email VARCHAR(100);

-- Удаление таблицы полностью
DROP TABLE Students;

```

* **DML (Data Manipulation Language) — Работа с данными:**

```sql
-- INSERT (Вставка)
INSERT INTO Students (first_name, last_name, group_id) 
VALUES ('Иван', 'Иванов', 101);

-- UPDATE (Обновление)
UPDATE Students 
SET group_id = 102 
WHERE student_id = 1;

-- DELETE (Удаление строк)
DELETE FROM Students 
WHERE group_id = 102;

-- SELECT (Выборка данных + JOIN, GROUP BY, HAVING)
SELECT g.group_name, COUNT(s.student_id) AS total_students
FROM Groups g
LEFT JOIN Students s ON g.group_id = s.group_id
WHERE g.is_active = TRUE
GROUP BY g.group_name
HAVING COUNT(s.student_id) > 5
ORDER BY total_students DESC;

```

*Разница между `WHERE` и `HAVING`:* `WHERE` фильтрует строки **до** группировки, `HAVING` фильтрует агрегированные результаты **после** `GROUP BY`.

### 4. Структура БД, Ключи и Целостность

* **Виды ключей:**
* *Суперключ:* Набор атрибутов, уникально идентифицирующий строку.
* *Потенциальный ключ (Candidate Key):* Минимальный суперключ (без избыточных атрибутов).
* *Первичный ключ (Primary Key, PK):* Выбранный потенциальный ключ для идентификации строк в таблице.
* *Составной ключ (Composite Key):* Первичный ключ, состоящий из двух и более столбцов.
* *Внешний ключ (Foreign Key, FK):* Поле, ссылающееся на PK другой таблицы для обеспечения ссылочной целостности.
* *Суррогатный ключ:* Искусственно созданное поле (обычно `INT AUTO_INCREMENT` или `UUID`), не несущее бизнес-смысла.


* **Поддержание целостности данных (Constraints):**
* `NOT NULL` — запрет пустых значений.
* `UNIQUE` — уникальность значений в столбце.
* `CHECK` — проверка условия (например, `CHECK (age >= 18)`).
* `FOREIGN KEY ... ON DELETE / ON UPDATE:`
* `CASCADE` — удаляет/обновляет связанные строки автоматически.
* `RESTRICT / NO ACTION` — запрещает удаление родительской строки при наличии зависимых.
* `SET NULL` — устанавливает `NULL` в зависимых строках.
