1. Основы Linux: файловая система, команды, права доступа.
   Главная особенность Linux - всё является файлом. Обычные документы, каталоги, устройства, процессы, сетевые интерфейсы и даже часть информации о системе представлены в виде файлов.
   В отличие от Windows, где есть несколько дисков (C:, D:), в Linux существует единое дерево каталогов, начинающееся с корня /.
   Основные каталоги, которые нужно понимать по их назначению:
   /
   Корень файловой системы. Отсюда начинается всё дерево.
   /home
   Домашние каталоги пользователей. Здесь находятся личные файлы.
   /root
   Домашний каталог администратора (root).
   /etc
   Конфигурация системы и приложений.
   /var
   Изменяемые данные: журналы (логи), кэш, базы данных, очереди.
   /usr
   Большинство установленных программ и библиотек.
   /bin, /sbin
   Основные исполняемые программы системы.
   /tmp
   Временные файлы.
   /dev
   Представление устройств в виде файлов.
   /proc
   Виртуальная файловая система с информацией о процессах и ядре.

Главная идея: файловая система - это не просто место хранения данных, а основной интерфейс взаимодействия с операционной системой.

Абсолютные и относительные пути
Путь может быть:
Абсолютным - начинается с /. Например: /etc/nginx/nginx.conf
Относительным - отсчитывается от текущего каталога. Например: documents/report.txt
Полезные обозначения:
`.` – текущий каталог;
`..` – родительский каталог;
`~` – домашний каталог пользователя.

Права доступа
Каждый объект в Linux имеет владельца и права доступа.
Права делятся на три категории:
Owner (u) - владелец;
Group (g) - группа;
Others (o) - остальные пользователи.
И три типа разрешений:
r (read) - чтение;
w (write) - изменение;
x (execute) - выполнение.

2. Управление пакетами.
   В Linux программы обычно не устанавливают, скачивая случайные установщики из интернета. Вместо этого используется менеджер пакетов - инструмент, который централизованно устанавливает, обновляет и удаляет программное обеспечение, автоматически отслеживая версии и зависимости.
   Ключевые понятия:
   Пакет - архив, содержащий файлы программы и метаданные: имя, версию, описание и список зависимостей.
   Репозиторий - хранилище пакетов (обычно сервер в интернете), из которого система получает и проверяет программы.
   Зависимости - другие пакеты, которые необходимы для работы устанавливаемой программы.
   Инструменты работы с пакетами делятся на два уровня:
   Низкоуровневые - работают с одним конкретным файлом пакета, но не разрешают зависимости сами (dpkg, rpm).
   Высокоуровневые - работают с репозиториями, находят и подтягивают зависимости автоматически (apt, dnf, zypper, pacman).

3. Настройка и управление сетевыми интерфейсами.
   Сетевой интерфейс - это средство, через которое операционная система взаимодействует с сетью. Им может быть физическая сетевая карта, Wi-Fi адаптер или виртуальный интерфейс, созданный системой или программами виртуализации.
   Для Linux сетевой интерфейс - такой же объект системы, как процесс или файл. Каждый интерфейс имеет имя (например, eth0, ens33, enp0s3, wlan0), собственный IP-адрес, состояние и набор параметров.
   Основные параметры сетевого интерфейса
   Для работы в сети интерфейс должен иметь несколько обязательных параметров.
   IP-адрес
   Маска подсети
   Шлюз (Gateway)
   DNS-сервер
   Статическая и динамическая настройка
   Существует два основных способа получения сетевых параметров.
   Статическая настройка. Администратор вручную задаёт: IP-адрес; маску; шлюз; DNS.
   Такой способ используют для серверов, поскольку их адрес не должен изменяться.
   DHCP автоматически выдаёт все необходимые параметры сети.
   Преимущества: не требует ручной настройки; удобно для рабочих станций; снижает вероятность ошибок.
   Недостаток - IP-адрес может измениться после повторного подключения.

Просмотр состояния сети
Современный Linux использует утилиту ip.
ip addr
показывает сетевые интерфейсы и их IP-адреса
ip link
отображает состояние интерфейсов
ip route
выводит таблицу маршрутизации

Управление интерфейсами
Интерфейс можно включать и отключать без перезагрузки системы.
Включение:
– sudo ip link set enp0s3 up
Отключение:
– sudo ip link set enp0s3 down
При необходимости можно назначить IP-адрес вручную:
– sudo ip addr add 192.168.1.100/24 dev enp0s3
Добавить маршрут по умолчанию:
– sudo ip route add default via 192.168.1.1
Следует понимать, что подобные настройки являются временными и будут потеряны после перезагрузки системы.
Постоянная настройка сети
Чтобы параметры сохранялись после перезагрузки, используются средства управления сетью.
Наиболее распространённые варианты:
Netplan - современные Ubuntu;
NetworkManager - рабочие станции и многие настольные дистрибутивы;
systemd-networkd - серверные системы;
сетевые сценарии (ifcfg, /etc/network/interfaces) - более старые версии некоторых дистрибутивов.

4. Управление пользователями и группами.
   Linux - многопользовательская система. Любое действие выполняется от имени какого-либо пользователя, а права доступа к файлам и ресурсам привязаны к пользователям и группам.
   Ключевые понятия:
   Пользователь - учётная запись с уникальным номером UID, домашним каталогом и командной оболочкой (shell).
   Группа - объединение пользователей с уникальным номером GID; удобно для выдачи общих прав сразу нескольким людям.
   Суперпользователь root - учётная запись с UID 0 и неограниченными правами. Повседневную работу под root вести не рекомендуется; для отдельных действий используют sudo.
   Информация о пользователях и группах хранится в текстовых файлах:
   Файл

   /etc/shadow
   зашифрованные пароли и параметры их устаревания
   /etc/group
   список групп и их участников
   /etc/sudoers
   правила предоставления прав через sudo

5. Настройка и использование SSH для удаленного доступа.
   SSH (Secure Shell) - это сетевой протокол, предназначенный для безопасного удалённого подключения к компьютеру.
   Главное отличие SSH от старых протоколов (например, Telnet) заключается в том, что весь передаваемый трафик шифруется. Это позволяет безопасно передавать команды, файлы и данные даже через недоверенные сети.
   Принцип работы SSH
   При подключении происходит несколько этапов:
   Клиент устанавливает соединение с сервером.
   Сервер подтверждает свою подлинность.
   Создаётся защищённый (зашифрованный) канал связи.
   Пользователь проходит аутентификацию.
   После успешной проверки открывается удалённая командная оболочка.
   Главная идея - администратор работает с удалённым компьютером так, словно находится непосредственно за ним.
   Подключение к удалённому серверу
   Подключение выполняется командой:
   ssh username@192.168.1.100
   или
   ssh username@example.com
   После успешной аутентификации пользователь получает доступ к командной строке удалённого компьютера.
   По умолчанию SSH использует TCP-порт 22.
   Аутентификация пользователей
   SSH поддерживает два основных способа входа.

1) По паролю - Пользователь вводит логин и пароль. Это самый простой вариант, однако он менее безопасен, так как пароль можно подобрать с помощью перебора.
2) По ключам. Более безопасный способ. Сначала создаётся пара ключей:
   закрытый (private key) - хранится только у пользователя;
   открытый (public key) - копируется на сервер.
   Основные меры безопасности
   При использовании SSH рекомендуется:
   – отключить вход под пользователем root;
   – использовать аутентификацию по ключам вместо паролей;
   – использовать сложные пароли и ключевые фразы;
   – ограничивать доступ с помощью брандмауэра;
   – регулярно обновлять OpenSSH и операционную систему.
   Эти меры значительно снижают вероятность несанкционированного доступа к серверу.

6. Управление процессами: мониторинг, завершение, планирование задач.
   Процесс - это выполняющийся экземпляр программы. Когда программа запускается, ядро выделяет ей уникальный номер PID и отслеживает её состояние, потребление памяти и процессорного времени.
   Ключевые понятия:
   PID - идентификатор процесса; PPID - идентификатор родительского процесса, запустившего данный.
   Демон (daemon) - процесс, работающий в фоне и обслуживающий систему (например, веб-сервер или планировщик).
   Приоритет (nice) - величина от −20 до 19, влияющая на то, сколько процессорного времени получит процесс (меньше значение - выше приоритет)

7. Работа с системными логами.
   Системные логи - это журналы, в которых операционная система и программы записывают информацию о своей работе.
   В логах фиксируются: запуск и остановка служб; ошибки и предупреждения; вход пользователей в систему; работа оборудования; события безопасности.
   Для администратора логи являются первым источником информации при поиске неисправностей. Вместо того чтобы гадать, почему возникла проблема, следует сначала посмотреть, что сообщает сама система.
   Где хранятся логи
   Большинство журналов располагается в каталоге: /var/log/
   Следует понимать, что набор логов может немного отличаться в зависимости от используемого дистрибутива.
   Наиболее важные файлы:
   /var/log/syslog
   Общий системный журнал (Ubuntu и Debian).
   /var/log/messages
   Общий системный журнал (RHEL, CentOS и др.).
   /var/log/auth.log
   События аутентификации и входа пользователей.
   /var/log/kern.log
   Сообщения ядра Linux.
   /var/log/dmesg
   Информация об обнаруженном оборудовании при загрузке.

Systemd Journal
В современных дистрибутивах Linux большинство служб записывает события в Systemd Journal. Для просмотра используется команда: journalctl
Наиболее полезные варианты:
Показать последние записи: journalctl -n 20
Просматривать журнал в режиме реального времени: journalctl -f
Показать сообщения конкретной службы: journalctl -u ssh
Таким образом можно быстро определить, почему служба не запускается или завершилась с ошибкой.
Практическое применение
Работа администратора почти всегда начинается с анализа логов.
Например:
не запускается веб-сервер - проверяются журналы службы;
пользователь не может войти в систему - анализируется auth.log;
не определяется оборудование - изучаются сообщения ядра;
служба аварийно завершается - просматривается её журнал через journalctl.
Главная задача - не искать проблему вслепую, а использовать информацию, которую уже записала операционная система.

8. Настройка и управление брандмауэром.
   Брандмауэр (firewall) - это система фильтрации сетевого трафика. Он анализирует проходящие пакеты и по заданным правилам решает, пропустить их или заблокировать, защищая узел от нежелательных подключений.
   Ключевые понятия:
   Правило (rule) - условие (порт, протокол, адрес) плюс действие: разрешить (accept), отбросить молча (drop) или отклонить с уведомлением (reject).
   Политика по умолчанию - что делать с пакетом, не подошедшим ни под одно правило. Безопасный подход - запрещать всё, что не разрешено явно.
   Порт и протокол - трафик описывается номером порта и протоколом (TCP или UDP), например 22/tcp для SSH.

В основе фильтрации в Linux лежит подсистема ядра netfilter, а инструменты работы с ней делятся на уровни:

Главная идея: брандмауэр - первая линия сетевой защиты. Основной принцип его настройки - «запретить всё и открыть только необходимое», чтобы минимизировать поверхность для атак.

9. Резервное копирование и восстановление данных.
   Резервное копирование (Backup) - это создание копии данных для их последующего восстановления в случае потери или повреждения.
   Главная цель резервного копирования - не сохранить данные любой ценой, а обеспечить возможность их быстрого восстановления.
   Виды резервного копирования
   Существует три основных типа резервных копий.

1) Полное (Full Backup). Копируются все выбранные данные.
   Преимущества: простое восстановление; высокая надёжность.
   Недостаток: занимает больше времени и места на диске.
2) Инкрементное (Incremental Backup). После полного резервного копирования сохраняются только изменения, произошедшие с момента предыдущей копии.
   Преимущества: минимальный объём хранения; быстрое создание.
   Недостаток: восстановление требует полной копии и всех последующих инкрементных архивов.
3) Дифференциальное (Differential Backup). После полного резервного копирования сохраняются все изменения с момента создания последней полной копии.
   Преимущества: восстановление проще, чем при инкрементном копировании.
   Недостаток: занимает больше места, чем инкрементные копии.

Основные инструменты резервного копирования
В Linux существует множество средств для создания резервных копий.
cp
копирование отдельных файлов
tar
создание архивов
rsync
синхронизация каталогов и резервное копирование
dd
создание побитовых копий дисков и разделов

Восстановление данных
Создание резервной копии имеет смысл только тогда, когда её можно восстановить.
Восстановление архива tar выполняется командой: tar -xzf backup.tar.gz
При использовании rsync восстановление выполняется обычной синхронизацией в обратном направлении: rsync -av /backup/user/ /home/user/
После восстановления рекомендуется проверить целостность данных и убедиться, что файлы имеют корректные права доступа.

Автоматизация резервного копирования
Регулярное создание резервных копий обычно автоматизируется.
Для этого используются:
cron - выполнение задач по расписанию;
systemd timers - современная альтернатива cron.
Автоматизация снижает вероятность того, что резервная копия не будет создана вовремя.

10. Основы скриптинга: Bash, автоматизация задач.
    Bash-скрипт - это текстовый файл с последовательностью команд, которые интерпретатор выполняет автоматически, одну за другой. Скрипты избавляют администратора от ручного повторения однотипных действий.
    Структура и запуск:
    В первой строке указывают shebang - путь к интерпретатору: #!/bin/bash.
    Файлу дают право на выполнение: chmod +x script.sh.
    Запускают: ./script.sh.

Основные элементы языка:
Элемент
Назначение
Пример
Переменные
хранение значений
NAME="Ivan BUDKO" - задать, $NAME - использовать
Ввод
чтение данных от пользователя
read answer
Аргументы
параметры, переданные скрипту

Условия

Функции

    Пример: скрипт резервного копирования:

#!/bin/bash
SRC="/home/user/data" # что копируем
DST="/backup" # куда копируем
DATE=$(date +%F) # текущая дата, например 2026-07-10

tar -czf "$DST/backup_$DATE.tar.gz" "$SRC"

if [ $? -eq 0 ]; then
echo "Резервная копия создана: backup\_$DATE.tar.gz"
else
echo "Ошибка при создании копии" >&2
fi

    Настоящая сила скриптов раскрывается в связке с планировщиком: если поместить такой скрипт в cron, резервное копирование будет выполняться по расписанию без участия человека.

Главная идея: скриптинг превращает ручную рутинную работу в надёжную автоматизацию. Один раз описанная последовательность действий выполняется одинаково точно и может запускаться по расписанию.
