# Операционные системы

> Материал для трека «МАИ», подготовленный по программе вступительного экзамена и конспекту mai.md.

### 1. Архитектура ОС

* **Монолитное ядро (Monolithic Kernel):** Все службы ОС (планировщик, файловая система, сетевой стек, драйверы) работают в едином адресном пространстве ядра (Kernel Space).
* *Плюсы:* Высокая скорость работы за счет отсутствия накладных расходов на межпроцессное взаимодействие (IPC).
* *Минусы:* Низкая надежность — сбой в одном драйвере рушит всю систему (Linux, Windows NT).


* **Микроядро (Microkernel):** В пространстве ядра остаются только базовые функции: управление памятью, планирование потоков и IPC. Остальные службы (драйверы, ФС) вынесены в пользовательский режим (User Space).
* *Плюсы:* Высокая надежность и модульность.
* *Минусы:* Высокие накладные расходы на переключение контекста и передачу сообщений между процессами (Minix, QNX).


* **Экзо-ядро (Exokernel):** Ядро не предоставляет абстракций оборудования, а только безопасно выделяет физические ресурсы (страницы памяти, блоки диска). Абстракции реализуются на уровне пользовательских библиотек (LibOS).

### 2. Управление процессами и планирование

* **Процесс vs Поток:** Процесс — экземпляр программы с собственным изолированным адресным пространством. Поток (Thread) — единица выполнения внутри процесса, потоки одного процесса разделяют общее адресное пространство.
* **Контекст процесса:** Состояние процессора (значения регистров, `PC`, `SP`), таблицы страниц памяти, открытые дескрипторы файлов. Хранится в **PCB** (Process Control Block).
* **Переключение контекста (Context Switch):** Сохранение состояния текущего процесса в PCB и загрузка состояния нового процесса. Высокозатратная операция.
* **Алгоритмы планирования:**
* **FCFS (First-Come, First-Served):** Невытесняющий. Процессы выполняются в порядке прихода. Недостаток: *эффект конвоя* (короткие процессы ждут длинный).
* **SJF (Shortest Job First):** Выполняет процесс с наименьшим временем исполнения. Оптимален по среднему времени ожидания, но требует знания времени выполнения заранее.
* **SRT (Shortest Remaining Time First):** Вытесняющая версия SJF. Если прибывает процесс с меньшим оставшимся временем, текущий вытесняется.
* **RR (Round Robin):** Вытесняющий. Каждому процессу дается квант времени (Time Slice). По истечении кванта процесс перемещается в конец очереди `Ready`.
* **Приоритетное планирование:** Выполняется процесс с наибольшим приоритетом. Проблема: *голодание* (Starvation) низкоприоритетных процессов. Решение: *старение* (Aging) — постепенное повышение приоритета со временем.

### 3. Синхронизация процессов

* **Критическая секция:** Участок кода, в котором процесс обращается к общему разделяемому ресурсу. Должен выполняться в режиме взаимного исключения (Mutual Exclusion).
* **Алгоритм Петерсона:** Программное решение задачи критической секции для двух процессов без аппаратной поддержки (использует флаги готовности `flag[2]` и переменную очередности `turn`).
* **Семафоры (Дейкстра):** Защищенная переменная `S`, управляемая двумя атомарными операциями:
* `wait(S)` / `P(S)`: уменьшает `S`. Если $S \le 0$, процесс блокируется.
* `signal(S)` / `V(S)`: увеличивает `S` и разблокирует ожидающий процесс.
* *Считающий семафор:* Управляет доступом к ресурсу с несколькими экземплярами.
* *Бинарный семафор (Мьютекс):* $S \in \{0, 1\}$.


* **Мониторы:** Высокоуровневая языковая конструкция (класс), автоматически обеспечивающая взаимное исключение внутри своих методов и использующая условные переменные (`wait()`, `signal()`).
* **Задача "Производитель-Потребитель" (Producer-Consumer):** Классическая проблема синхронизации буфера ограниченного размера. Требует 3 семафоров: мьютекс для доступа к буферу, `empty` (счетчик свободных ячеек) и `full` (счетчик занятых ячеек).

### 4. Управление памятью и виртуальная память

* **Распределение памяти:**
* *Фиксированные разделы:* Память делится на статические блоки. Приводит к **внутренней фрагментации**.
* *Переменные разделы:* Блоки выделяются динамически под размер процесса. Приводит к **внешней фрагментации** (решается компактизацией).


* **Свопинг (Swapping):** Выгрузка неактивного процесса целиком из ОЗУ на диск и обратно.
* **Оверлеи (Overlay):** Устаревший метод, когда программист явно разбивает программу на сегменты, подгружаемые в одну и ту же область памяти по мере необходимости.
* **Виртуальная память и Страничные нарушения:**
* Виртуальный адрес преобразуется MMU в физический через таблицу страниц (Page Table).
* *Страничное нарушение (Page Fault):* Исключение, возникающее при обращении к странице, отсутствующей в физической памяти (бит присутствия $P=0$). Ядро загружает страницу с диска (Swap/Paging file).


* **Алгоритмы замещения страниц:**
* **FIFO:** Вытесняет самую старую страницу. Подвержен **Аномалии Билэди (Belady's Anomaly)** — увеличению количества страничных нарушений при увеличении числа выделенных фреймов памяти.
* **LRU (Least Recently Used):** Вытесняет страницу, к которой не обращались дольше всего. Не подвержен аномалии Билэди.
* **OPT (Optimal):** Вытесняет страницу, которая не потребуется дольше всего в будущем (теоретический эталон).
* **NFU (Not Frequently Used):** Вытесняет страницу с наименьшим счетчиком обращений.

### 5. Тупики (Deadlocks)

* **Четыре необходимых условия возникновения тупика (Условия Коффмана):**
1. *Взаимное исключение:* Ресурс не может использоваться одновременно несколькими процессами.
2. *Удержание и ожидание:* Процесс удерживает ресурсы, ожидая выделения других.
3. *Отсутствие принудительного изъятия (No Preemption):* Ресурс нельзя отобрать у процесса насильно.
4. *Круговое ожидание:* Существует замкнутая цепь процессов $\{P_0, P_1, \dots, P_n\}$, где $P_i$ ожидает ресурс, удерживаемый $P_{i+1}$.


* **Модель Холта (Граф распределения ресурсов):** Двудольный граф, где вершины — процессы и ресурсы. Замкнутый цикл в графе (при единичных экземплярах ресурсов) указывает на тупик.
* **Алгоритм банкира (Дейкстра):** Алгоритм предотвращения тупиков. Проверяет, останется ли система в **безопасном состоянии** (Safe State), если удовлетворить запрос процесса на ресурс.

### 6. Драйверы устройств

* **Типы устройств:**
* *Символьные (Character devices):* Передают данные в виде потока байтов без возможности адресации (клавиатуры, последовательные порты).
* *Блочные (Block devices):* Обмениваются данными блоками фиксированного размера (512 Б, 4 КБ) с произвольным доступом (SSD, HDD).


* **Взаимодействие:** Драйвер маскирует особенности железа, предоставляя ядру стандартный API (операции `open`, `read`, `write`, `ioctl`).
